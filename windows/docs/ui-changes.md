# UI changes

- Settings → Shortcuts offers fixed, persistent Hold Ctrl (default) and Ctrl+Alt+D toggle methods. Only the selected method acts; changing methods restores mouse input and waits for Ctrl release before rearming Hold Ctrl.
- Ctrl is still read globally by the existing Windows cursor poll. The toggle runs only in Rust on the global hotkey press; the Windows hotkey registration suppresses key repeat. Custom actions colliding with the active fixed toggle are refused and flagged in Settings.
- Settings → Island Appearance offers Original Coucou and Windows Dark Frosted. Saved `glassmorphism` preferences migrate to `windowsDarkFrosted`; absent or invalid preferences keep their defaults.
- Windows Dark Frosted uses a fixed charcoal surface at 88% opacity, a subtle Windows accent tint, white edge highlights and soft depth. UISettings.GetColorValue(Accent) supplies the accent; ColorValuesChanged updates it live. An unavailable accent uses the charcoal CSS fallback.
- CSS backdrop filtering is limited to internal WebView card content where supported. There is no native Acrylic, gray native backdrop, or claimed desktop blur.
- Both click-through methods use the same 35% opacity and clear the preset tint, blur, decorative wash, shadow and edge reflections. Disabling click-through restores the selected appearance.
- Home, expanded views, chat, permissions and notifications share the root appearance. The upload canvas no longer paints a black island background over Windows Dark Frosted during drag, upload or attachment choice.
- Wardrobe now defaults to Ctrl+Alt+W and remains customizable. Existing duplicate, external hotkey conflict and installed AltGr layout checks still protect other shortcuts and typing (ABNT2 uses AltGr+W for `?`).
- Tests cover method switching, mouse acceptance, fixed-key conflicts, saved preferences and migration, Windows accent/fallback, appearance restoration and the upload canvas regression. Live native toggle/mouse routing and accent change notifications still need a Windows desktop check.
- General keeps **Auto-launch with agents**, default OFF, persisted as `autoLaunchWithAgents` independently of Windows startup. Its description is "Automatically open Coucou when a connected coding agent starts working." Stage 2A updates only the support note to "Supports Codex CLI prompts and Hermes session starts." All existing interface languages include the text. Existing ON/OFF values are preserved; there is no Hermes-specific switch.
- The switch has an accessible name, description and updated pressed state. Island appearance, click-through and shortcuts are unchanged. Implementation, checks and the pending Windows desktop procedure are in `docs/backend-flow.md`.
- Stage 2A: Hermes and Codex share the backend startup queue and retain separate monitoring pills. The frontend hook handler, answers, Chat and permissions are unchanged. All 327 frontend tests passed, including Stage 1.5 prompt exclusion, simultaneous Hermes/Codex monitoring, answers, and permission isolation with Auto-Launch ON/OFF. No native island/tray GUI result is claimed.
- Stage 1.5: `UserPromptSubmit` no longer appends `prompt` or the legacy `message` input to agent monitoring steps. It appends the ticker's existing neutral `…` label and retains the `thinking` state. The event and its payload still pass through the relay/backend; Codex Auto-Launch, session/turn IDs and permission handling are unchanged.
- The root cause was the shared frontend handler storing user input as a ticker step. After clearing `finalLine`, the finished card's fallback could display that step, while the expanded `finished` view stayed open. A new prompt now returns that view to the default monitoring view only when its own pill is focused. Chat, another pill's card, and a folded island keep their existing behavior. The previous Stop timer is still cancelled; Stop output still becomes the displayed final answer. Ticker animation and tool/diff steps remain unchanged.
- Verification for Stage 1.5 covers prompt/legacy-message exclusion, finished-to-thinking transitions, two rapid Codex prompts across ticker animation frames on a fake DOM, the subsequent agent answer, preservation of island Chat history/state, all known agents and a custom agent, and OFF/ON Auto-Launch compatibility. Passed: TypeScript `tsc --noEmit`, `cargo check --workspace --offline`, 168 frontend tests across hooks/live diff/Chat/agents/Auto-Launch/pills/FSM/plan, 39 relay/Auto-Launch Rust tests, and 2 backend startup-queue tests. Frontend files ran separately with `--test-isolation=none`. The regression tests detected the original bug before the patch; all final checks passed. Fake-DOM tests do not establish native GUI behavior.
- Windows retest: Quit the running build, run `rtk npm run tauri -- build --no-bundle`, and open `target\release\coucou.exe`. Focus the Codex monitoring pill, wait for an answer, then submit a new prompt while the finished card is still visible (within 5.2 seconds). The card should return to monitoring with `thinking`/`…`, show tool activity if present, and display the next answer after Stop. Repeat with two rapid prompts, an empty/tool-free response, the overview ticker, a folded island, and Codex working behind another pill. Verify a new CLI prompt does not replace an active island Chat or change its history. Smoke-test another connected agent, permissions, Auto-Launch after Quit, Hold Ctrl/Click-Through, Dark Frosted and shortcuts. No installer or native GUI test was performed for this patch.
- Stage 2A.5: `Stop` now surfaces the finished card for the event's agent, regardless of the focused/Main Tool pill. A short-lived snapshot carries that agent's name, session and final answer through the island's hidden-to-home transition and the existing 5.2-second pill cleanup. The Main Tool and focused pill are not changed; the card never falls back to a user prompt when no answer is available.
- Nearby finishes are shown in order for the configured auto-close interval, then the island returns to its previous hidden, compact or overview state. Duplicate `Stop` events do not replay the sound or popup. Chat, Settings, file drag, hover/pin and live permission cards keep the screen; the finishing pill is badged instead. Sound and pill state still use the existing `Stop` path. No separate window, Auto-Launch or relay change was made.
- Stage 2A.5 frontend tests cover Hermes/Codex/OpenCode identity and answer isolation, queued finishes, duplicate/stale sessions, hidden-state restoration, prompt exclusion and non-interruption. Native Windows GUI behavior still requires manual verification. The current Main Tool picker only offers workspace-category pills, so Hermes is not currently a selectable Main Tool; this stage leaves that Settings rule unchanged.
- Stage 2A.6: Agent pill labels now share a flex row with their 24 px animated mascot slots. A fixed gap clears the mascot canvas, while `minmax(0, 1fr)` grid columns and a shrinking label keep long names inside each pill. Long labels use ellipsis and expose the full name through the pill tooltip. Right padding leaves the existing notification badge clear. The compact mascot grid, pill colors, animations, popup behavior and both appearances are unchanged.
- Stage 2A.6 verification: TypeScript and 172 relevant frontend tests passed. The added Edge layout test covers catalog names, idle/working/notification pills, both appearances and 100%/125%/150% scaling when browser process creation is available; it was skipped here because the sandbox rejects browser child processes. Vite's build was blocked by the same `spawn EPERM` restriction, so no native Windows GUI or screenshot result is claimed.
- Stage 2B: Settings → General retains the single Auto-launch with agents toggle and its existing localized description. The older Codex/Hermes-only support note was removed because four agents now share this option; its unused translation entry was removed too. Main Tool, pill layout, popup and both appearances are unchanged. Backend behavior and Windows update steps are in `docs/backend-flow.md`.
- Stage 2B.5: The finished card already used the Stop snapshot for its name and answer, but the island canvas still took mascot color, outfit and animation state from the focused pill or Main Tool. The finished card and canvas now use the same snapshot, including queued responses and pills removed after Stop. A non-main sender has no Main Tool outfit, even in compact mode; switching a popup outfit cancels an in-progress outfit fade before the first frame. User focus, Main Tool, mascot designs and normal outfit animation remain unchanged.
- Stage 2B.5 verification: TypeScript and 167 relevant frontend tests passed, including Codex, Hermes, Claude Code and OpenCode answer cards, queued popups, compact outfit, focus preservation and the outfit transition. The default test runner and Vite build were blocked by sandbox spawn EPERM; frontend tests passed when run as individual files without child processes. Native Windows GUI and screenshot appearance still require manual verification.
- Stage 2C: Antigravity and Antigravity IDE share the existing Antigravity pill and mascot. When a new conversation becomes active, the pill clears steps from the previous conversation; late tool and Stop events from the older conversation cannot replace its monitoring or finished popup. Main Tool, focused pill, themes and popup rendering stay on their existing paths. The official Stop payload has no answer text, so the finished card uses its existing generic fallback.
- Stage 3: Settings → General adds `Auto-quit when agents finish`, default OFF, with a fixed backend wait of 10 minutes. The toggle is independent of Auto-launch and Windows startup. The island answers a backend quit check only when it is unattended; expanded views, Chat history or draft, Settings, permission cards, response popups, uploads, dragging, focused Coucou windows, and recent interaction defer shutdown. Antigravity preview still shows `Session finished` when no verified final answer is provided. Pill, mascot, themes, and popup rendering were not changed.
- Stage 4: Settings → General adds a compact `Quit after` dropdown with 5, 10, 15, 30, and 60 minutes. It stays visible but disabled while Auto-Quit is OFF. The default is 10 minutes, and both the label and choices use the existing ten-language catalog. No other Settings control changes.
